There's a quote on a sticky note above my monitor. It says: *"when we lose
our principle, we invite chaos."* I used to think it was about ethics. It is,
partly. But mostly it's about software.

ผมมีโพสต์อิทแผ่นเล็ก ๆ แปะอยู่เหนือจอ มันเขียนว่า
*"เมื่อใดที่เราละทิ้งหลักการ เมื่อนั้นเราเชิญความวุ่นวายเข้ามา"*
ตอนแรกผมคิดว่ามันพูดถึงเรื่องจริยธรรม จริงอยู่ บางส่วน

## What "principle" looks like in code

A principle is a small rule that's cheap to follow on a normal day, and
expensive to break on a hard one. Things like:

- One source of truth for any piece of state
- Server boundaries are explicit, never implicit
- The build either passes cleanly or doesn't ship

```ts
// Each rule is small. Each shortcut is small. Their sum is not.
function shortcut(): never {
  throw new Error("we'll fix this in v2");
}
```

I don't keep these because they're elegant. I keep them because, on the third
hard day in a row, I am too tired to make good decisions from scratch. The
principle decides for me.
